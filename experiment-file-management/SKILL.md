# 实验项目文件管理

## 开始处理

1. 从用户打开或指定的目录确定项目根目录。优先识别根目录 `AGENTS.md` 中的 `experiment-project` 标记，读取同目录 `README.md`、`notes/experiment_log.md` 和 `notes/changes.md` 中与本次任务有关的内容。已有项目规范优先。
2. 根据来源、用途和现有脚本的实际读写关系确认输入及批次。相同扩展名或相同主文件名可能对应不同仪器或处理阶段。无法确认的旧文件按原位读取，在记录中标明来源待确认。
3. 新建实验项目时，按需建目录并写项目 `README.md`。将 [项目识别模板](assets/project-agents.md) 写入根目录 `AGENTS.md`。已有 `AGENTS.md` 时保留现有内容，在项目首次采用此规范时补入兼容的识别段落。沿用旧项目的输入路径和已有脚本入口，将新增产物直接写到适当目录。

## 分类

| 目录 | 内容和例子 |
|---|---|
| `data/raw/<批次>/` | 仪器采集、直接导出、现场照片和原始校准记录，如 `1hz100v.lvm`、`force_export.csv`、`scope_capture.tdms`、`sample_03.tif`、`calibration.xlsx` |
| `data/processed/` | 滤波、对齐、校准、分段后的数据及后续计算用的特征表，如 `force_filtered_v01.csv`、`signals_aligned_v01.mat` |
| `scripts/` | 分析、绘图和导出代码，以及项目自有的辅助函数，如 `process_force.m`、`plot_response.py`、`analysis.ipynb` |
| `config/` | 分析用参数、通道映射和单位换算，如 `filter_settings.json`、`channel_map.csv` |
| `results/figures/`、`results/tables/`、`results/reports/` | 正式图件、最终汇总和报告，如 `force_response_v02.pdf`、`metrics_summary_v01.xlsx`、`experiment_report_v01.docx` |
| `notes/` | 实验记录、修改要求、实验方案和参考资料，如 `test_protocol.pdf` |
| `.cache/` | 可重建预览及临时文件，如 `force_response_preview.png` |

用采集日期和序号标识批次，如 `2026-11-07_b01`。沿用可信的既有批次编号。缺少日期时用已知编号或 `batch_01` 一类标识，并注明日期待确认。批次专属的处理数据、配置及结果按需用同名子目录区分。批次处理方法一致时共享脚本，由参数选择批次和配置。方法独立时将专用脚本放在 `scripts/<批次>/`。

## 补充、修改与版本

- 同一轮补采归入该批次。独立复测新建批次。保留采集文件原名及内容。仪器重发的更正数据保留原名，放入同批次的 `reissued_r01/`，下一次更正用 `reissued_r02/`。在 `notes/experiment_log.md` 记录更正前后的相对路径及实际采用的输入。
- 用户补充的实验事实按日期和批次写入 `notes/experiment_log.md`。聊天里的分析、图表或报告修改要求写入 `notes/changes.md`，记录日期、更新点、对应文件或版本、状态（待办或已完成）。项目要求在这里维护。用户明确提出适用于所有项目的规则时，更新本技能。
- 新保留的处理数据和正式交付物用 `主题_内容_vNN.扩展名`，默认使用简短的小写英文和下划线，如 `force_response_1hz_v01.png`。同一成果的各格式共用文件主名和版本。已有版本实质更新时，在同系列的最高版本上递增并保留旧版。在临时目录迭代工作稿，确认本轮输出后再写入对应版本。更新点写在 `notes/changes.md`。
- 脚本和运行配置保持稳定文件名。每个正式结果在项目索引或变更记录中关联批次、输入及处理数据的相对路径、运行入口、参数版本和外部依赖。已有 Git 的项目可引用包含实际脚本和配置的提交号。提交未包含所用内容，或迁移包不含可用的提交历史时，在 `history/` 下镜像成果所在的项目相对目录，再用 `<成果主名>_vNN/` 保存所用脚本和配置的副本，保持项目相对目录结构并随项目带走。若需复现该版，在临时项目副本中恢复这些路径后运行。

## 交付与迁移

- 实验图默认导出 PNG。用户明确要求 PDF 时再导出 PDF。已有 PDF 随历史版本归档。
- 每次新增分析产物后，更新 `README.md` 中的批次索引、可执行入口、依赖和正式结果位置。记录实际使用的 MATLAB、工具箱、Python 包等外部依赖和已知版本。避免用当前电脑上的绝对路径作为长期引用。
- 脚本从自己的位置定位项目根目录，再拼接项目相对路径。MATLAB 可用 `mfilename('fullpath')` 和 `fullfile`，Python 可用 `Path(__file__).resolve()`，并按脚本实际层级定位根目录。先验证输出文件和记录里的路径，再汇报交付位置及版本。
- 用户要求迁移旧项目时，先核对输入、脚本和输出的引用。复制项目到目标位置，带上根目录的 `AGENTS.md`、`README.md`、数据、脚本、配置、正式结果、记录和所需历史。迁移包可省略可重建缓存。更新包内引用，在新位置或从另一个工作目录验证入口。来源不清的文件也应保留并注明。源项目的清理按用户的单独要求执行。
- 告知用户在 Codex 打开迁移后的项目根目录并从那里开始聊天。根目录 `AGENTS.md` 给出项目类型和索引入口。若换电脑时也需要使用完整的个人技能，将本技能目录同步到新电脑的个人技能目录。
